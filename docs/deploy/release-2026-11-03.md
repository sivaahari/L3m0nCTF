# Release `release-2026-11-03`: what is in it, and what to do when it is put on the cloud

This is the release candidate for the event. **It is not deployed.** The cloud platform (when it runs again) is still at `release-2026-10-22`; putting this release on the cloud is a cloud update and is done only when the project owner says so, step by step. This page is the whole upgrade, written so that it can be followed without me.

## What changes for a player

- **Every page the player uses has the L3m0n-TV look**, on the real platform: sign-in (email, Google, CTFtime), registration in steps (account, e-mail check, studio), the channels board and the programme panel (flag form, hints, instances), the notifications page and the bell, the Guide, the scoreboard, the studio page and the settings page, the password reset pages and the error pages. Before this release only the sign-in page and the error pages looked like it.
- **The rules on names and passwords are enforced on the server**, not only in the browser: a username is 3 to 24 letters, digits, dots, dashes and underscores (no reserved names such as `root` or `admin`, no look-alike or invisible characters); an e-mail address must be a permanent one (no throw-away domains, no second form of an address already in use); a password has at least 12 characters, does not contain the player's username or e-mail, and is not a common password. The settings page applies them too.
- **The lists of other studios and players are closed** (a studio's public page, the list of studios, the list of players, a player's public page): only the crew keeps them. The scoreboard page is for signed-in players; the public ranking is the CTFtime feed.
- **`/challenges` sends everybody to `/board`**, so signing in lands on the board.
- The scoreboard and the Guide show the news crawl; the Settings page says 12 characters like the rule.

## What changes for the crew

Nothing in the crew's own pages changes in this release. The new server-side rules apply to the crew's API calls too, except that the crew may give any account any name or address. The crew's account pages and the admin API are untouched.

## What changes under the hood

- The image: Pillow 13.0.0, certifi 2026.10.23, setuptools 84.2.1 and OpenSSL 3.0.22-1~deb12u2 (39 + 1 + 1 + 1 advisories fixed), and new pinned digests for MariaDB, Redis and nginx (see `docs/security/dependency-bumps.md`). CTFd stays at 3.8.8 on purpose; its 3.8.9 release contains only the certifi fix (which we now have) and a `pip` bump (our image has no `pip`).
- CI tells the truth now: every job passes. The instancer and operations tests that need their own services run in their own job.
- The move kit (`tools/export-state.sh`, `tools/import-state.sh`) is in this release (it was only in the repository before).

## Upgrading from `release-2026-10-22`

1. **No database migration.** No release since 22 October adds a table or a column.
2. Check out the tag on the machine, `tools/verify-image.sh` after the build (it now also checks OpenSSL and the new libraries), then `tools/compose.sh up -d --wait --force-recreate` with the production settings the runbook (`docs/deploy/go-live-runbook.md`, part 4) names. The new MariaDB image is a patch of the same 10.11 series: the existing data directory is read as it is; **take a backup first** (`tools/backup.sh`), as for every deployment.
3. Players may have to sign in again after the containers are recreated.
4. **Checks after the deploy** (each a few seconds, from outside, as in the 22 October log entry in `docs/deploy/verification-log.md`): `/login` shows the new sign-in page; `/register` shows the first step of the registration; `/board` as a visitor sends you to sign in; `/challenges` sends you to `/board`; `/teams` and `/users` answer 404 for a visitor; `/api/v1/users/me` refuses a weak password with the 12-characters sentence; the crew can still open `/admin`.
5. **If anything is wrong:** `docs/runbooks/10-rollback-deploy.md` (the previous tag, the same steps).

## Still not in it (said plainly)

A mail service (sign-up, e-mail confirmation and password reset need one; without it a new player cannot finish registering); the instancer is not switched on in this release's production settings (web challenges need a challenge host; TCP challenges need the next instancer work); the story line of a programme and the way into the comics and the finale (being built); the challenges themselves.
