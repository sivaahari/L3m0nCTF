# Audit of the three teammate branches and the integration (18 October 2026)

Written by the lead engineer (an AI assistant working for the project owner) on 18 October 2026, 02:00 to 08:00 IST. Plain words. No secrets.

**What this is.** On 17 October three teammates (each with their own coding agent) pushed the pieces of the build they were given: `feat/instancer` (per-team challenge instances), `feat/identity` (anti-abuse and Continue with Google) and `feat/operations` (busy mode, backups, mail relay, monitoring, runbooks). This page records how they were checked, what was found, what was fixed here, and what the teammates must still do.

**The short version.**
- All three branches were based on the same `pre-deployment` commit and merged **without a single conflict**, because they touch separate folders.
- Everything the teammates claimed to have proved was **re-run on a clean build of the merged code**, and it held, with the exceptions listed below.
- Reading the security-critical code found **real defects in all three**. The ones that were small enough were **fixed here, test first** (each test fails on the old code and passes on the new). The larger ones are written up as follow-up prompts for the teammates.
- **The per-team instancer is not ready for production** and stays off. The sign-in code and the operations pieces are fit for the first deployment, with the fixes below.

## 2. What was found

Severity words: **High** can lose data or let a stranger do harm; **Medium** is a real weakness or a bug players would meet; **Low** is polish or a deviation from the specification.

### 2.1 Instancer (`feat/instancer`, 8 commits, 45 files, about 5,700 lines)

| # | Sev. | Finding | Status |
|---|---|---|---|
| I-1 | **High** | **The router (which anybody on the internet can reach) believed a declared `Content-Length` and read the whole body before checking the 10 MB limit.** One request with `Content-Length: 4000000000` could use all of its 256 MB, with no valid host name needed. There was also no limit on header lines and no timeout for a slow client | **Fixed** (413 before reading; 431 for over 100 header lines; 408 after 10 s). 4 tests |
| I-2 | Medium | `assert_safe` (the one function that decides whether a container may be created) did not look at `HostConfig.Mounts` (the modern bind-mount field), `PublishAllPorts`, device and cgroup fields, and **let the user `00` through** (Docker reads it as UID 0) | **Fixed**, 22 tests. Any user must now be a plain non-zero number |
| I-3 | Medium | A container spec that `assert_safe` refused left its Docker network (and a TCP port) behind, so a player could use up Docker's networks by asking again and again | **Fixed**, test added |
| I-4 | Medium | The per-team flag check compared two `str` values with `hmac.compare_digest`, which raises `TypeError` for non-ASCII text: **one accented letter in a submitted flag gave the player a server error** | **Fixed** (compares bytes). Tests added |
| I-5 | Low | The instancer's token check had the same problem, and an empty `ROUTER_TOKEN` would have accepted an empty bearer | **Fixed**, 2 tests |
| I-6 | Low | The branch added a `pip.conf` line to `docker/ctfd/Dockerfile` (the image has no pip; that file is not part of the piece) | **Reverted** |
| I-7 | Low | The handoff gave a wrong path for the fixture image (`demo-web`; the folder is `web`) | Fixed in the docs |
| I-12 | Medium | The player API forwarded the request's `ttl_seconds` to the instancer: only the instancer's development switch stood between a player and an instance that lives for a year | **Fixed**: ignored unless the platform runs with `L3MON_INSTANCES_TTL_OVERRIDE=1`. 2 tests |
| I-8 | Medium | The router buffers a whole backend response with no size limit (a player who gets code execution in their own instance can make it send gigabytes and get the router killed, taking every team's instance offline), collapses several `Set-Cookie` headers into one, sends two `Content-Length` headers, never uses its per-instance connection limit, and says WebSockets are supported when they are not | **Open: follow-up prompt, task R1** |
| I-9 | Medium | `compose.instancer.yml` runs the instancer in development mode (`INSTANCER_DEV=1`) with the example manifest, which allows unpinned images and a `ttl_seconds` override | **Open: do not use this overlay on a server; follow-up task R2** |
| I-10 | Low | The manager holds one lock while it calls Docker, so one slow call stalls every team | **Open: R4** |
| I-11 | Info | TCP routing, the isolation proof and several hosts are Milestones 2 and 3 (due 31 October and 5 November) and are **not delivered yet**, as planned | Follow-up prompt |

What was good: the design (labels as the only state, an internal network per instance, the router attached to it, a socket proxy that allows only containers and networks, the pinned proxy image), the per-team flag derivation matches the specification and its three test vectors, quotas and cool-downs are tested, the unique key makes eight simultaneous starts give one row on a real MariaDB, and the end-to-end test (start, reach through the router, correct flag, another team's flag refused, renew, restart both services, stop, cool-down) passed.

### 2.2 Anti-abuse and Google sign-in (`feat/identity`, 2 commits, 36 files, about 5,000 lines)

| # | Sev. | Finding | Status |
|---|---|---|---|
| G-1 | Low | A blocked disposable registration stored the **full email address** in the crew-visible evidence (the specification said "counted, not shown per person") | **Fixed** (domain only), test added |
| G-2 | Medium | Every registration, and every Google sign-up, loads **all** accounts and normalises each email (`Users.query.all()`): thousands of objects per request at the moment CTFd workers are scarcest | **Open: follow-up prompt, task F1** |
| G-3 | Medium | The login CAPTCHA is required for **everyone at an address** after three failures there. Behind a campus NAT three typos make every student solve a CAPTCHA | **Open: F2** |
| G-4 | Low | The disposable-domain list is a starter list of about 50 domains | **Open: F3** (needs the owner's permission to download the full open list once) |
| G-5 | Low | An unknown signing key bypasses the one-refresh-a-minute limit (not exploitable: the token only comes from Google's own endpoint over TLS in answer to our request) | **Open: F4** |
| G-6 | Low | Smaller points (the Turnstile address setting, wording "wrong attempts" versus "attempts", the address stored twice, the theme contract) | **Open: F5** |

What was good, and checked by reading: state is single-use, constant-time compared and expires after ten minutes; PKCE and nonce are set; the redirect address is fixed from the platform host, never from the request; the token verifier accepts RS256 only and checks issuer, audience, expiry, issued-at, nonce and `email_verified`; weak keys are refused; **accounts are found only by Google's `sub`, never by email, and an existing email account is never linked** (so no account takeover); administrator and banned accounts are refused; a new Google account gets no studio and goes through CTFd's own team step; the routes answer 404 until configured; test hosts are allowed only when `L3MON_AUTH_TEST_MODE=1`, which the overlay never sets. The guard's hooks cost nothing on unrelated routes (proved by test), and it wraps the three CTFd views without replacing them.

### 2.3 Operations (`feat/operations`, 5 commits, 69 files, about 7,200 lines)

| # | Sev. | Finding | Status |
|---|---|---|---|
| O-1 | **High** | **`tools/ops/backup.sh` silently fell back to the example age key** when no real recipients file existed. That key's private half is printed in age's own documentation, so a backup made this way (every player's email and API token inside) could be opened by anyone who finds it | **Fixed**: no fallback; a recipients file that holds the example key is refused unless the tests say so. 4 tests |
| O-2 | Medium | `/readyz` connected to hosts called `db` and `cache` whatever the platform's settings said (so it answered 503 on any machine without those names, including every test run), and its one-second budget only worked under gevent (a hung check took 5 seconds) | **Fixed**: it asks the platform's own database and cache; the budget is kept in a thread pool. 2 new tests |
| O-3 | Medium | The event-phase gauge was labelled `before/during/ended`, but the clock says `before/live/paused/ended`: **during the event no series was 1**, so every alert built on the phase would have been blind | **Fixed**, test added |
| O-4 | Medium | The busy mode's two new `limit_conn` lines (in `location /` and the flag route) **replaced** the per-address cap that those locations inherited (nginx does not combine them), so one address could hold the whole 250-connection allowance and make the site answer "busy" to everybody | **Fixed**: the per-address cap is repeated beside them; a test reads the config and fails if a location has a `limit_conn` without it |
| O-5 | Low | The mail relay's redelivery test expected two messages in a log that the catcher's restart wipes, so it could never pass | **Fixed** (the relay itself was right) |
| O-8 | Medium | The load test's target allow-list matched by **prefix** (`localhost.evil.example` and `127.0.0.1.nip.io` passed) and listed a **misspelt domain**, `play.l3monctf.xyz` (no zero), which belongs to somebody else. A load test aimed at a third party is an attack | **Fixed**: the whole host name must be on the list in `run.sh` and `safety.js`; the real name `play.l3m0nctf.xyz` replaces the misspelling. 5 new refusal cases |
| O-10 | Medium | The load test has three allow-lists that must agree: `run.sh` (on the laptop), `safety.js` (inside the k6 container) and `allowlist.json`. `run.sh` hands the container the address `nginx:8080`, which `safety.js` did not list; the old prefix match had let it through by accident, and the exact match of O-8 made **every real run refuse to start**. `run.sh` also lacked `host.docker.internal` that the other two listed | **Fixed**: the three lists are identical. A new test compares them and checks that every address `run.sh` gives the container is accepted; it failed before the fix and named both gaps. The k6 smoke run passes again |
| O-9 | Low | `docs/deploy/identity.md` told the owner to register `l3monctf.xyz` with Google (the domain is `l3m0nctf.xyz`) | **Fixed** |
| O-6 | Info | `l3mon_ops` replaces the session interface's open and save methods so that a Redis outage does not take pages down. A Redis problem therefore logs players out quietly instead of showing an error. This is intended resilience, tested, and accepted; the runbook says what players see | Accepted |
| O-7 | Info | MariaDB now writes binary logs (up to 100 MB each, two days), nginx joins the `ops` network, TRUSTED_HOSTS gains `ctfd` and `localhost` when the `ops` overlay is on (reachable only inside the Docker network), and cAdvisor, node exporter and the log shipper need a separate profile (`host-metrics`) that does not work on Docker Desktop | Documented in the hosting guide |

What was good: the static busy, down and maintenance pages work without the application (tested by stopping it), flag submissions have their own cap, the maintenance switch lets the crew through, the mail relay queues and redelivers (tested with a catcher that goes down and comes back), no relay for strangers, every container is hardened and only nginx publishes a public port in production (checked with `docker compose config`), monitoring ports are on the loopback only, and the runbooks and the dress-rehearsal kit exist.
