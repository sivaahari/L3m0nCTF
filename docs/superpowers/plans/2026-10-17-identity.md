# SP5 & SP8: Anti-abuse (`l3mon_guard`) and Continue with Google (`l3mon_auth`) (implementation plan)

> Built test-first, milestone by milestone, with independent verification. Measure, then decide; nothing here is changed on a feeling. All rules adhere to L3m0nCTF 2026 platform standards.

**Goal:** Provide full anti-abuse protection (registration constraints, Cloudflare Turnstile CAPTCHA, per-team flag submission limits, crew evidence queue and review API/page) via `plugins/l3mon_guard` and secure OpenID Connect sign-in via `plugins/l3mon_auth` ("Continue with Google") without degrading standard email/password authentication or Login with CTFtime.

**Why now:** Registration and account creation represent major operational hazards (email spam/delays, fake account bursts, multi-account team abuse). Google sign-in guarantees verified email addresses without deliverability issues, while the anti-abuse suite protects the platform against credential stuffing, flag brute-forcing, and multi-team collusion.

## 1. What was read and measured in the codebase

1. **CTFd Version & Pinning:**
   - Platform pinned to CTFd 3.8.8 (`docker/ctfd/Dockerfile#L5`).
   - Every plugin must invoke `from CTFd.plugins.l3mon_core.versions import check_ctfd_version; check_ctfd_version()` at initialization (`plugins/l3mon_core/__init__.py#L29`).
2. **View and Hook Mechanics in CTFd:**
   - `auth.register` (`CTFd/auth.py#L22`): Validates user inputs, manages `verify_emails`, checks account limits and whitelist/blacklist.
   - `auth.login` (`CTFd/auth.py#L90`): Validates user credentials, sets session.
   - `auth.reset_password` (`CTFd/auth.py#L170`): Password recovery flow.
   - Wrapping view functions via `app.view_functions[endpoint]` at plugin startup executes checks before stock handler and returns identical CTFd form error structures without patching core files.
3. **Existing Integrations (`l3mon_ctftime`):**
   - In `plugins/l3mon_ctftime/oauth.py`, configuration is read per request (`client_id()`, `client_secret()`). Secrets are read from environment or files under `/run/secrets/`.
   - `safe_next()` rejects protocol-relative URLs (`//`) and backslashes (`\`).
   - `Users.oauth_id` is an integer reserved strictly for CTFtime user IDs; it cannot be reused for Google OAuth subjects (which are string identifiers).
   - `l3mon_ctftime` creates teams and users directly on models; name policy checks must not interfere with `l3mon_ctftime` studio creation.
4. **Database Collation & Concurrency:**
   - MariaDB 10.11 uses `utf8mb4_unicode_ci` at `REPEATABLE READ`.
   - Redis operations: `cachelib`'s Redis `add` uses separate `SETNX` and `EXPIRE`. Therefore, rate limiting and atomic failure counters must execute in a single atomic transaction/pipeline (`INCR` + `EXPIRE`).
   - Clock time is strictly sourced from `CTFd.plugins.l3mon_core.clock.now()`.
5. **Contract for Other Plugins:**
   - Instancer and future plugins call `CTFd.plugins.l3mon_guard.evidence.record(kind, team_id=..., user_id=..., challenge_id=..., other_team_id=..., detail=...)`.
   - The contract must never raise exceptions, never store plaintext flags, truncate detail to 200 plain-text characters, and be callable even if database transactions fail.

## 2. Key Decisions and Alternatives Rejected

| Topic | Options | Choice | Rationale |
|---|---|---|---|
| **View Interception** | (a) Replace CTFd auth blueprints<br/>(b) Wrap `app.view_functions` in `load()` | **(b)** Wrap `app.view_functions` | Preserves all core routing, upstream url_for references, and hooks installed by other plugins (e.g. `l3mon_theme`). Errors pass as standard form errors. |
| **Team Name Policy Scope** | (a) SQLAlchemy model event listeners<br/>(b) View and API route validation | **(b)** View & API routes only | `l3mon_ctftime` creates teams directly via models using official CTFtime team names which must remain bit-for-bit identical for rating feeds. Model listeners would break CTFtime sync. |
| **Google Subject Mapping** | (a) Overload `Users.oauth_id`<br/>(b) New table `l3mon_identity` | **(b)** `l3mon_identity` | `Users.oauth_id` is an Integer column belonging to CTFtime. Google `sub` is a string (up to 255 chars). Separate table prevents collisions and enables clean provider-subject pairs. |
| **Account Linking on Google Login** | (a) Auto-link by verified email<br/>(b) Refuse auto-linking if existing account with same email exists | **(b)** Refuse auto-link | Prevents account takeover attacks where a pre-existing password account is hijacked by a federated identity without explicit credential verification. |
| **CAPTCHA Verification Failure Mode** | (a) Fail closed everywhere<br/>(b) Fail closed on register; fail open on login/reset | **(b)** Fail closed on register; fail open on login/reset | If Cloudflare Turnstile has an outage, existing players must not be locked out of the competition; however, automated spam registration bursts are still stopped. Unverified events are recorded as evidence. |
| **Login Failure Counting** | (a) Relational DB table<br/>(b) Redis atomic counter per IP and username bucket | **(b)** Redis atomic counter | High performance, zero DB load on failed login attacks, bounded TTL window (e.g., 15 minutes). |
| **Team Flag Attempt Limits** | (a) Core patch to `/attempt`<br/>(b) Flask `before_request` hook or blueprint wrap | **(b)** Intercept `/api/v1/challenges/attempt` | Standard plugin extension point. Returns standard 429 with `Retry-After` header when limit exceeded. |

## 3. Interfaces and Data Contracts

### 3.1 Evidence Contract (`plugins/l3mon_guard/evidence.py`)
```python
def record(
    kind: str,
    *,
    team_id: int | None = None,
    user_id: int | None = None,
    challenge_id: int | None = None,
    other_team_id: int | None = None,
    detail: str = "",
) -> None:
    ...
```
- Valid `kind` values:
  - `flag_reuse`
  - `burst`
  - `shared_address`
  - `registration_burst`
  - `captcha_unverified`
  - `disposable_email_blocked`
  - `name_policy_blocked`
- Sanitization: `detail` stripped, truncated to max 200 chars, processed with `CTFd.plugins.l3mon_core.text.plain_text`. Any flags (matching `L3m0n{...}` or similar) stripped/refused.
- Safe execution: Wrapped in `try...except Exception: _log.warning(...)`, never propagating errors to callers.

### 3.2 Jinja Context Contracts
- `l3mon_guard`:
  ```python
  {
      "captcha": {
          "sitekey": "<public site key or empty>",
          "register": bool,
          "login": bool,
          "reset": bool,
      }
  }
  ```
  `login` is true only when the visitor's IP address or targeted user has recent failed logins recorded in Redis and `sitekey` is configured. `register` and `reset` are true whenever `sitekey` is configured.

- `l3mon_auth`:
  ```python
  {
      "google": {
          "enabled": bool,
          "url": "/auth/google"
      }
  }
  ```
  `enabled` is true only when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` (or its secret file) are present and non-empty.

### 3.3 Crew Review API (`/api/v1/l3mon/admin/guard/`)
- `GET /api/v1/l3mon/admin/guard/evidence`:
  - Query params: `status`, `kind`, `team_id`, `limit` (max 200), `before_id`.
  - Returns paginated list of evidence records (newest first).
- `POST /api/v1/l3mon/admin/guard/evidence/<id>`:
  - Body: `{"status": "new|reviewed|dismissed|actioned", "note": "<max 200 chars>"}`.
  - Updates record and logs action via `CTFd.plugins.l3mon_core.audit.record`.
- `DELETE /api/v1/l3mon/admin/guard/evidence?older_than_days=30`:
  - Prunes evidence older than specified days for data retention compliance.

### 3.4 Crew Admin Web Page (`/admin/l3mon/guard`)
- Accessible only to crew/administrators.
- Renders server-side shell with no inline scripts/styles (external script in `assets/`).
- Allows filtering by status, team, kind, and 1-click status transitions.

## 4. Database Models and Migrations

### 4.1 Table: `l3mon_evidence` (Migration in `plugins/l3mon_guard/migrations/`)
- `id`: Integer, primary key, autoincrement.
- `kind`: String(40), indexed.
- `team_id`: Integer, ForeignKey to `teams.id` (ondelete="SET NULL"), nullable.
- `other_team_id`: Integer, ForeignKey to `teams.id` (ondelete="SET NULL"), nullable.
- `user_id`: Integer, ForeignKey to `users.id` (ondelete="SET NULL"), nullable.
- `challenge_id`: Integer, ForeignKey to `challenges.id` (ondelete="SET NULL"), nullable.
- `detail`: String(200), default="".
- `address`: String(45), nullable. (Only stored here for evidence audit; pruned by retention).
- `created_at`: DateTime, not null.
- `status`: String(20), default="new", indexed ("new", "reviewed", "dismissed", "actioned").
- `reviewer_id`: Integer, ForeignKey to `users.id` (ondelete="SET NULL"), nullable.
- `note`: String(200), default="".

### 4.2 Table: `l3mon_identity` (Migration in `plugins/l3mon_auth/migrations/`)
- `id`: Integer, primary key, autoincrement.
- `provider`: String(32), not null (e.g. "google").
- `subject`: String(255), not null.
- `user_id`: Integer, ForeignKey to `users.id` (ondelete="CASCADE"), not null.
- Unique constraint: `(provider, subject)`.

   - Define `l3mon_evidence` in `plugins/l3mon_guard/models.py`.

   - Implement `plugins/l3mon_guard/evidence.py` adhering to the contract.
3. **Crew API & Review Page:**
   - Admin routes under `/api/v1/l3mon/admin/guard/evidence`.
   - Crew interface at `/admin/l3mon/guard`.
   - Audit integration via `CTFd.plugins.l3mon_core.audit`.
4. **Registration Policies:**
   - Disposable email blocklist: `plugins/l3mon_guard/data/disposable_domains.txt` loader and checker.
   - Email normalization helper: strip tags after `+`, normalize gmail/googlemail dots, NFKC normalize, block zero-width and bidi characters. Duplicate check across existing users.
   - Team name policy: NFKC + casefold, collapse whitespace, block reserved impersonation words (`admin`, `ctfd`, `l3mon`, `staff`, etc.), exempt crew.
   - Wrap `auth.register` and team creation/rename endpoints.
5. **Milestone 1 Test Suite:**
   - Unit tests for evidence recording and sanitization.
   - View tests for registration blocklists and email normalization.
   - Team name policy tests on SQLite and MariaDB.
   - Hook cost test confirming zero DB queries on unaffected requests.
6. **Milestone 1 Documentation & Push:**
   - Initial handoff report in `docs/handoff/identity.md`.

### Milestone 2: Turnstile, Limits, and Abuse Scenarios (Due Oct 31)
1. **Cloudflare Turnstile CAPTCHA:**
   - Implement client and server-side verification against Cloudflare `siteverify`.
   - Login failure counters in Redis (`INCR` + `EXPIRE`).
   - Fail-open for login/reset, fail-closed for register when Cloudflare is unreachable.

   - Context processor injecting `l3mon_guard`.
2. **Per-Team Flag Submission Limits:**
   - Intercept `/api/v1/challenges/attempt` to track team submission frequency in Redis.

3. **NAT & Abuse Detection:**

   - `shared_address` and `registration_burst` evidence producers with deduplication.

### Milestone 3: "Continue with Google" (`l3mon_auth`) (Due Nov 5)
1. **Plugin Skeleton & Version Guard:**
   - Create `plugins/l3mon_auth/__init__.py` with `check_ctfd_version()`.
2. **Identity Model & Migration:**
   - Define `l3mon_identity` and Alembic migration.
3. **OIDC Flow with PKCE:**
   - Endpoints `/auth/google` and `/auth/google/callback`.
   - State generation (16 bytes hex, 10 min TTL, single use), PKCE challenge (S256), nonce validation.
   - ID Token validation using `cryptography` (RS256, JWKS caching, audience, issuer, expiry, `email_verified=true`).
   - Strict account resolution: find solely by `(provider, sub)`. No auto-linking to existing email accounts.
   - Context processor injecting `l3mon_auth`.
4. **Mock Google Provider & Test Suite:**
   - Local mock OIDC fixture generating test RSA keys.
   - Comprehensive test coverage for token errors, replay, spoofing, name clashes, and untouched CTFtime auth.
